# دفتر ستاره

یک دفتر فارسی و خلوت برای مطالعه، برنامه و پیشرفت تحصیلی؛ با نسخهٔ وب مستقل، اندروید آفلاین و سورس نسخهٔ سروری.

[باز کردن نسخهٔ وب](https://matinmt3.github.io/daftar-setareh/) · [دانلود اندروید](https://github.com/matinmt3/daftar-setareh/releases/latest) · [راهنمای وب](https://matinmt3.github.io/daftar-setareh/guide/) · [حریم خصوصی](https://matinmt3.github.io/daftar-setareh/privacy/)

## چه چیزی ساده‌تر شده است؟

- صفحهٔ «امروز» یک کار اصلی دارد: ثبت مطالعه. آمار و ابزارهای ثانویه از کار روزانه جدا شده‌اند.
- منوی کوتاه‌تر، رنگ‌های آرام، متن خواناتر و جزئیات اختیاری جمع‌شونده، روی موبایل و دسکتاپ.
- ورودی زمان منفی یا اعشاری به عدد دیگری تبدیل نمی‌شود؛ خطای روشن نشان داده می‌شود.
- وب مستقل بدون ثبت‌نام کار می‌کند؛ تاریخ‌ها و انتخاب تاریخ شمسی‌اند و اعداد فارسی پشتیبانی می‌شوند.

## نسخهٔ وب مستقل

نسخهٔ آنلاین روی GitHub Pages اجرا می‌شود. اطلاعات دفتر در مرورگر همان دستگاه می‌مانند و به سرور برنامه فرستاده نمی‌شوند. پس از بازشدن کامل اولیه، فایل‌های برنامه برای استفادهٔ بدون اینترنت ذخیره می‌شوند. پشتیبان JSON و کارنامهٔ قابل چاپ دارد؛ برای PDF در پنجرهٔ چاپ «Save as PDF» را انتخاب کن.

دادهٔ مرورگر و اندروید خودکار همگام نمی‌شوند. فایل پشتیبان معتبر را می‌توانی با انتخاب خودت جابه‌جا کنی. پشتیبان رمزگذاری نشده است؛ پیش از پاک‌کردن مرورگر، تغییر دستگاه یا حذف برنامه آن را در محل امن نگه دار.

### اجرای وب مستقل روی کامپیوتر

```powershell
npm.cmd ci
npm.cmd run build:web
npm.cmd run preview:web
```

سپس [http://127.0.0.1:4400/daftar-setareh/](http://127.0.0.1:4400/daftar-setareh/) را باز کن. برای اجرا روی دستگاه خودت فایل خصوصی سرور یا کلید پیامک لازم نیست. داده‌های این آدرس محلی با نسخهٔ آنلاین جدا هستند؛ انتقال با پشتیبان انجام می‌شود.

### آزمون و ساخت

```powershell
npm.cmd test
npm.cmd run test:web
```

برای آزمون مرورگر در صورت نیاز `npx playwright install chromium` را اجرا کن. کد وب مستقل در `web-offline/` و خروجی قابل انتشار در `static-dist/` ساخته می‌شود. گردش GitHub Actions پس از موفقیت آزمون‌های وب سروری، اندروید و مرورگر مستقل، شاخهٔ اصلی را روی Pages منتشر می‌کند.

## اندروید مستقل

APK نسخهٔ جدید از بخش [Releases](https://github.com/matinmt3/daftar-setareh/releases/latest) در دسترس است. حداقل Android 8.0 است؛ برنامه به اینترنت، کامپیوتر یا سرور نیاز ندارد. راهنمای امکانات، ساخت و پشتیبان در [android/README-fa.md](android/README-fa.md) قرار دارد. کلید خصوصی امضا و داده‌های شخصی در سورس منتشر نمی‌شوند.

## نسخهٔ وب سروری اختیاری

راهنمای زیر مربوط به نسخهٔ Next.js با حساب و پایگاه‌دادهٔ SQLite سرور است. سورس آن حفظ شده و برای اجرا به Node.js و فضای پایدار SQLite نیاز دارد. نسخهٔ آنلاین GitHub Pages از وب مستقل بالا استفاده می‌کند.

دفتر ستاره یک برنامهٔ وب فارسی و راست‌به‌چپ برای دانش‌آموزان است: گزارش مطالعهٔ روزانه، آزمون و نمره، کارنامهٔ خودکار، برنامهٔ تکرارشونده، هدف، تحلیل پیشرفت و تنظیمات حساب. رابط کاربری فقط فارسی است و تاریخ‌ها بر پایهٔ تقویم جلالی و منطقهٔ زمانی تهران نمایش داده می‌شوند.

## امکانات

- ورود با شمارهٔ موبایل ایران و کد یک‌بارمصرف، بدون رمز عبور
- ثبت گزارش روزانه با زمان مطالعهٔ هر درس، کارها، متن تأمل و گزارش تکمیلی
- ثبت آزمون، محاسبهٔ میانگین وزنی درس‌ها، روند و نقاط قوت و ضعف
- ساخت خودکار کارنامهٔ هفتگی و ماهانه با نسخهٔ قابل چاپ
- برنامهٔ مطالعهٔ تکرارشونده، یادآور درون‌برنامه‌ای و اعلان مرورگر
- هدف‌های مطالعه، کار و میانگین آزمون با پیشرفت زنده
- داشبورد و صفحهٔ تحلیل با نمودارهای مطالعه و نمره
- مدیریت درس‌ها، پروفایل و حذف حساب
- حساب نمایشی با دادهٔ نمونه برای مرور سریع همهٔ بخش‌ها

## پشتهٔ فنی

- Next.js 16 (App Router) و React 19
- TypeScript سخت‌گیرانه و Tailwind CSS 4
- SQLite داخلی Node.js (`node:sqlite`) با مهاجرت‌های نسخه‌دار و ریپازیتوری‌های تایپ‌شده
- آیکون‌ها با Lucide، نمودارها با Recharts و صحنهٔ سه‌بعدی صفحهٔ اصلی با React Three Fiber
- Vitest برای تست واحد/یکپارچه و Playwright برای تست انتها‌به‌انتها

## پیش‌نیاز

- Node.js 22.13 یا جدیدتر؛ از این نسخه `node:sqlite` بدون فلگ آزمایشی در دسترس است. خروجی این پروژه با Node.js 26.4.0 بررسی شده است.
- npm

## راه‌اندازی محلی

```powershell
npm.cmd ci
if (-not (Test-Path .env.local)) { Copy-Item .env.example .env.local }
```

سپس `.env.local` را ویرایش کنید. حداقل این مقادیر را تنظیم کنید:

```dotenv
DATABASE_PATH=./.data/daftar-setareh.db
AUTH_SECRET=یک-رشته-تصادفی-حداقل-۳۲-کاراکتری
SMS_PROVIDER=console
DEMO_MODE=true
```

برای ساخت یک کلید تصادفی:

```powershell
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
```

برنامه را اجرا کنید؛ ساختار پایگاه‌داده خودکار آماده می‌شود. حساب دمو در اولین ورود نمایشی ساخته می‌شود:

```powershell
npm.cmd run dev -- --hostname 127.0.0.1 --port 3002
```

برنامه روی [http://127.0.0.1:3002](http://127.0.0.1:3002) بالا می‌آید. برای اجرای مجدد پروژهٔ موجود، فایل `.env.local` و پوشهٔ `.data` را حفظ کنید؛ اجرای seed یا reset برای شروع لازم نیست.

### ورود

- در حالت `SMS_PROVIDER=console` یک شمارهٔ معتبر وارد کنید؛ کد تأیید در رابط کاربری و ترمینال سرور نمایش داده می‌شود و پیامک واقعی ارسال نمی‌شود.
- با `DEMO_MODE=true` دکمهٔ «ورود به حساب نمایشی» در صفحهٔ ورود فعال می‌شود. شمارهٔ حساب نمایشی `09120000000` است.
- حساب نمایشی به‌صورت خودکار با درس، آزمون، گزارش، برنامه و هدف نمونه ساخته می‌شود.

> حالت `console` فقط برای توسعه است و در محیط تولید مجاز نیست. حساب نمایشی نیز نباید در محیط عمومی فعال بماند.

## متغیرهای محیطی

| متغیر | الزام | توضیح |
| --- | --- | --- |
| `DATABASE_PATH` | بله | مسیر فایل SQLite. برای تست می‌تواند `:memory:` باشد. |
| `AUTH_SECRET` | در تولید بله | کلید امضای کد یک‌بارمصرف و امنیت نشست؛ حداقل ۲۴ کاراکتر. |
| `NEXT_PUBLIC_APP_URL` | خیر | آدرس عمومی برنامه. |
| `SITE_URL` | هنگام انتشار | origin دامنهٔ واقعی بدون مسیر، query یا fragment؛ پیش از build تنظیم شود. برای لوکال، پورت درخواست به‌صورت خودکار استفاده می‌شود. |
| `SMS_PROVIDER` | بله | `console`، `kavenegar` یا `none`. |
| `KAVENEGAR_API_KEY` | برای کاوه‌نگار | کلید سرویس پیامک. |
| `KAVENEGAR_SENDER` | برای کاوه‌نگار | شمارهٔ فرستنده. |
| `DEMO_MODE` | خیر | `true` ورود سریع نمایشی را فعال می‌کند. |
| `CRON_SECRET` | برای زمان‌بندی | کلید محافظت از مسیر ساخت کارنامه‌ها. |

## تست انتها‌به‌انتها

Playwright به‌طور پیش‌فرض Chromium نصب‌شده را استفاده می‌کند. در صورت نیاز:

```powershell
npx playwright install chromium
```

اگر دانلود مرورگر در دسترس نیست، از Chrome نصب‌شدهٔ سیستم استفاده کنید:

```powershell
$env:PLAYWRIGHT_CHANNEL="chrome"; npm run test:e2e
```

تنظیمات Playwright یک سرور توسعه روی پورت `3105` و پایگاه‌دادهٔ جداگانهٔ `.data/e2e.db` با حساب نمایشی فعال اجرا می‌کند. آزمون‌ها صفحهٔ معرفی و ورود، گردش گزارش/برنامه/آزمون/هدف/درس، ذخیرهٔ تنظیمات، خطای شبکه و نمایش و تقویم در عرض ۳۲۰ پیکسل را پوشش می‌دهند. سرور موجود دیگری را روی پورت تست اجرا نکنید؛ داده‌های این پایگاه فقط برای QA هستند.

```text
  server/

```

## منطق دامنه

- تاریخ‌ها به‌صورت `YYYY-MM-DD` ذخیره می‌شوند و هفته از شنبه آغاز می‌شود.
- نمرهٔ هر آزمون به درصد نرمال می‌شود؛ آزمون‌های بدون نمره در محاسبه نمی‌آیند ولی نمرهٔ صفر معتبر است.
- میانگین هر درس در صورت وجود وزن، وزنی است؛ وزن خالی برابر ۱ در نظر گرفته می‌شود.
- میانگین کل، میانگین میانگین درس‌های معتبر است. روند تنها با حداقل سه آزمون و آستانهٔ نیم درصد محاسبه می‌شود.
- هر روز می‌تواند یک گزارش اصلی و چند گزارش تکمیلی داشته باشد.
- سری برنامه حداکثر ۱۲۰ روز و ۱۵۰ جلسه تولید می‌کند.
- کارنامه‌ها به‌صورت تنبل ساخته می‌شوند و با تغییر دادهٔ منبع، اثر انگشت آن‌ها به‌روز می‌شود.

## زمان‌بندی کارنامه‌ها

مسیر `GET` یا `POST` روی `/api/cron/report-cards` کارنامه‌های اخیر را می‌سازد. درخواست باید یکی از این دو حالت را داشته باشد:

```text
Authorization: Bearer <CRON_SECRET>
```

یا پارامتر `?secret=<CRON_SECRET>`. بدون تنظیم `CRON_SECRET` مسیر پاسخ `503` می‌دهد.

## محدودیت‌های شناخته‌شده

- ارسال پیامک واقعی فقط با پیکربندی کاوه‌نگار انجام می‌شود؛ حالت پیش‌فرض توسعه پیامک نمی‌فرستد.
- اعلان مرورگر فقط هنگام باز بودن برنامه کار می‌کند؛ اعلان پس‌زمینه یا پوش وجود ندارد.
- هیچ پروفایل عمومی یا اشتراک‌گذاری اجتماعی وجود ندارد.
- داده‌ها در SQLite محلی نگهداری می‌شوند و برای استقرار چندنمونه‌ای به پایگاه‌دادهٔ شبکه‌ای نیاز است.
- رابط کاربری عمداً فقط فارسی و راست‌به‌چپ است.

## بررسی سلامت

```text
GET /api/health
```

پاسخ موفق شامل `{"ok":true,"service":"daftar-setareh"}` است و در صورت خطای پایگاه‌داده پاسخ `503` برمی‌گردد.

## استقرار

1. `npm run build` را اجرا کنید.
2. مقادیر محیطی تولید را تنظیم کنید: `DATABASE_PATH`، `AUTH_SECRET`، پیکربندی کاوه‌نگار و `CRON_SECRET`.
3. `DEMO_MODE` را `false` بگذارید و `SMS_PROVIDER=console` را در تولید استفاده نکنید.
4. مسیر پایگاه‌داده را روی فضای ذخیره‌سازی پایدار قرار دهید و از آن نسخهٔ پشتیبان بگیرید.
5. زمان‌بند خارجی را برای `/api/cron/report-cards` با هدر `Authorization` تنظیم کنید.

## SEO و آمادگی محتوایی

چهار صفحهٔ عمومی `/`، `/guide`، `/about` و `/privacy` دارای عنوان و توضیح مستقل، canonical، تصویر اشتراک‌گذاری و دادهٔ ساختاریافتهٔ مرتبط با متن قابل‌مشاهده هستند. `robots.txt` و `sitemap.xml` به‌صورت پویا با origin معتبر ساخته می‌شوند. فضای شخصی، ورود، راه‌اندازی حساب و API با noindex محافظت می‌شوند؛ کنترل دسترسی حساب جداگانه برقرار است.

امتیاز Lighthouse SEO یک سنجش محلی فنی است. اسکریپت آمادگی محتوا ۱۸ معیار داخلی با شواهد HTTP/HTML را بررسی می‌کند و امتیاز جهانی GEO نیست. انتشار روی دامنهٔ واقعی، HTTPS، خزش و نمایه‌شدن و ارجاع موتورهای هوش مصنوعی به بررسی بعد از انتشار نیاز دارند. برای تولید، `SITE_URL` را پیش از build به دامنهٔ واقعی تغییر دهید؛ مقادیر لوکال را منتشر نکنید.

## نسخهٔ مستقل اندروید

پروژهٔ بومی در `android/` قرار دارد. این نسخه برای گوشی مستقل طراحی شده و به سرور وب یا localhost متصل نمی‌شود. داده‌های آن در فضای خصوصی برنامه روی گوشی ذخیره می‌شوند و با نسخهٔ وب همگام نمی‌شوند. راهنمای ساخت، پشتیبان‌گیری JSON و خروجی PDF در `android/README.md` آمده است. APK نهایی و گزارش آزمون همراه بستهٔ تحویلی ارائه می‌شوند.
